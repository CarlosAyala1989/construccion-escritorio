# Pruebas automatizadas — RF-03 Bloqueo de interfaz local

## Alcance

- **Requisito:** RF-03 — el cliente de escritorio no permite capturar hasta que el operador haya seleccionado un espacio de trabajo válido.
- **Aplicación:** `construccion-escritorio`.
- **Componente:** `src/capture_context.py`.
- **Requisitos no funcionales relacionados:** RNF-07 (recuperación tras fallos) y RNF-11 (Windows 10/11 x64). La suite valida las reglas de contexto, pero no simula un escáner ni certifica compatibilidad nativa de Windows.
- **Aislamiento:** los permisos de base de datos se sustituyen por un doble en memoria; no se requiere MariaDB ni hardware.

## Casos de prueba

| ID | Tipo de prueba | Funcionalidad verificada | Criterio de verificación | Automatización |
|---|---|---|---|---|
| CP-RF03-01 | Unitaria (de componente) | Precondición de sesión | Sin sesión activa, la captura falla con `SESSION_REQUIRED_ERROR`. | `test_unitaria_bloquea_la_captura_sin_sesion` |
| CP-RF03-02 | Integración | Revalidación de permisos y contexto | La selección se consulta en el origen de permisos y se actualiza con sus metadatos vigentes. | `test_integracion_valida_y_actualiza_el_espacio_asignado` |
| CP-RF03-03 | Funcional | Inicio de captura | El flujo operador → espacio válido → sesión activa devuelve el espacio y el identificador de sesión correctos. | `test_funcional_habilita_la_captura_con_un_espacio_valido` |
| CP-RF03-04 | Rendimiento/estrés | Validación repetida del contexto | 1.000 validaciones consecutivas terminan en menos de 5 s y consultan permisos en cada ciclo. | `test_rendimiento_valida_mil_ciclos_sin_bloqueos` |
| CP-RF03-05 | Aceptación automatizada | Revocación del espacio seleccionado | Si el espacio deja de estar asignado, se elimina del contexto y se bloquea una nueva captura. | `test_aceptacion_revoca_el_espacio_y_vuelve_a_bloquear` |

## Ejecución y resultado

```bash
python -m unittest discover -s tests -p 'test_rf03*.py' -v
```

El mismo comando se ejecuta en GitHub Actions mediante `.github/workflows/pruebas-rf-03.yml`. La salida del trabajo y el resumen de categorías quedan disponibles en la ejecución de Actions. La suite es headless, por lo que no genera una captura de pantalla de la interfaz.

**Resultado local:** 5/5 casos aprobados con Python 3.14.6; duración total observada: 0,001 s.

## Límites

La aceptación automatizada reproduce el contrato de bloqueo con una fuente de permisos simulada. No reemplaza la aceptación manual del selector visual, ni mide el tiempo de recuperación física de un escáner o la compatibilidad de controladores OEM.
